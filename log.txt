### Implementation Components

The following modules were implemented:

#### `code/data_loader.py`

Responsible for:

* loading structured datasets
* normalizing input records
* resolving dataset relationships
* preparing financial profiles
* loading financial events
* processing payment options
* resolving request-related information
* integrating message/image-derived information

#### `code/simulator.py`

Responsible for:

* constructing the financial timeline
* simulating daily balances
* applying income and expense events
* applying planned payments
* evaluating cash-flow feasibility
* checking minimum-balance constraints
* performing the required 90-day simulation

#### `code/plan_ranker.py`

Responsible for:

* generating candidate payment plans
* filtering infeasible plans
* comparing feasible plans
* applying deterministic lexicographical ranking
* selecting the best valid plan

#### `code/explainer.py`

Responsible for:

* generating concise explanations
* describing why a plan was selected
* communicating important financial trade-offs
* ensuring explanations remain consistent with the simulation result

#### `code/evaluate.py`

Responsible for:

* evaluating predictions against available sample ground truth
* validating prediction structure
* checking expected fields
* reporting evaluation results

#### `code/main.py`

Responsible for:

* orchestrating the complete pipeline
* loading the dataset
* generating predictions
* validating the output
* writing the final CSV
* preparing the submission package

### Design Principles

The implementation follows several important principles:

1. **Deterministic behavior**
   The same input should produce the same prediction.

2. **Data-driven reasoning**
   Decisions are based on the supplied financial data rather than assumptions.

3. **Multimodal resolution**
   Information available through messages and images is incorporated into the financial model.

4. **Feasibility before optimization**
   Plans must first satisfy financial constraints before ranking is performed.

5. **Transparent ranking**
   Candidate plans are compared using explicit deterministic rules.

6. **Modular architecture**
   Each major responsibility is isolated into a dedicated module.

7. **Strict output compliance**
   The final prediction file must match the required HackerRank output contract exactly.
